# 3. Product Philosophy

MVPCompanion is not primarily about generating feature lists.

The central idea is:

> Better product decisions before you build.

A common failure mode is moving directly from:

Idea → Features → Screens → Coding

MVPCompanion introduces a systematic clarification process before detailed implementation.

The core principle is:

> Progressive clarification.

The process starts with an uncertain idea and progressively clarifies:

- the problem
- the user
- the value
- the product
- the context
- the jobs
- the scope
- the experience
- the information architecture
- the data
- the requirements
- the learning goals
- the technical boundaries
- the MVP boundary

The goal is not to make the product specification unnecessarily large.

The goal is to make the product sufficiently clear.

---

# 4. Central Product Promise

MVPCompanion aims to help a person move from:

> "I have an idea."

to:

> "I understand what I should build, why I should build it, for whom, what belongs in the MVP, and what I need to learn."

The resulting MVP should be:

- Valuable
- Viable
- Buildable

The MVP is also a learning instrument.

It should test important assumptions and create observable learning, rather than merely demonstrate that software can be built.

---

# 5. Method Principle

The central quality principle is traceability.

The conceptual chain is:

Problem
→ User
→ Outcome
→ Job
→ Capability
→ Requirement
→ Acceptance Criterion
→ Metric

Every important requirement should be traceable backwards to a meaningful user problem and forwards to an observable outcome.

Features should not exist merely because they are interesting.

A feature should have a clear relationship to a core user job and the product's value proposition.

# 6. MVPCompanion Process

The current underlying process contains 15 stages.

These stages are the source methodology for the website.

## Stage 1 — Idea

Question:
What could this be?

Output:
Idea hypothesis / Idea Brief

## Stage 2 — Problem

Question:
What real problem exists?

Output:
Problem Statement + evidence/assumptions

## Stage 3 — User

Question:
Who has the problem?

Output:
Primary User Profile + Target/Non-Target Segment

## Stage 4 — Value

Question:
Why does solving it matter?

Output:
JTBD + Value Proposition + Benefits + USP + Positioning

## Stage 5 — Product

Question:
What is the product fundamentally?

Output:
Product Mental Model + high-level entity map

## Stage 6 — Context

Question:
How does the object/user evolve?

Output:
Lifecycle model

## Stage 7 — Jobs

Question:
What must users accomplish?

Output:
Prioritized Jobs-to-be-Done / Core Use Cases

## Stage 8 — Scope

Question:
What is the smallest useful solution?

Output:
MVP Feature Map + Out-of-Scope List

## Stage 9 — Experience

Question:
How does the user get value?

Output:
Core User Flows + Screen Inventory

## Stage 10 — Information Architecture

Question:
How is the product organized?

Output:
Information Architecture + navigation model

## Stage 11 — Data Model

Question:
What entities and fields are needed?

Output:
MVP Entity/Data Model

## Stage 12 — Specification

Question:
What exactly must be built?

Output:
Functional Requirements + Acceptance Criteria

## Stage 13 — Learning

Question:
How will we know it works?

Output:
Success Metrics + Learning Questions

## Stage 14 — Technical Boundaries

Question:
What technical boundaries matter?

Output:
High-level architecture + technical constraints

## Stage 15 — MVP Boundary

Question:
Where exactly do we stop?

Output:
Scope statement + prioritized feature list + exclusions

# 8. Homepage Goals

The homepage has five primary goals.

1. Make MVPCompanion immediately understandable.
2. Explain why systematic clarification matters.
3. Introduce the MVPCompanion method.
4. Show the relationship between Method, Book, Website and App.
5. Give visitors a clear first action.

The homepage should not attempt to document the complete method.

It should create enough understanding and curiosity to invite the visitor into the method.

---

# 9. Primary Homepage Audience

The initial audience is people who have an app or digital product idea and want to work more systematically before development.

Relevant groups include:

- founders and entrepreneurs
- people with an early product idea
- product people
- builders and developers
- technically oriented people who may otherwise focus on implementation before sufficiently clarifying product and business questions

The website should remain understandable to newcomers.

Avoid assuming advanced product-management terminology.

---

# 10. Homepage Story

The homepage should follow this conceptual narrative:

1. I have an idea.
2. An idea is not yet a product.
3. Before building, important questions need to be clarified.
4. MVPCompanion provides a systematic way to clarify them.
5. The method progressively turns uncertainty into clarity.
6. The result is a valuable, viable and buildable MVP.
7. The method can be learned through the book, explored through the website and eventually applied through the app.
8. The visitor can start with their own idea.

# 12. Visual Direction

The website should be:

- clean
- minimal
- modern
- editorial
- structured
- calm
- highly legible
- spacious

The visual identity should communicate:

- clarity
- structure
- thinking
- progression
- confidence
- simplicity

Avoid:

- generic SaaS aesthetics
- excessive gradients
- excessive rounded cards
- stock photography
- fake product screenshots
- excessive animations
- visual clutter
- marketing hype
- AI-generated decorative imagery

The site should feel closer to:

> Editorial publication + product methodology + modern digital product

than:

> Generic AI startup landing page

---

# 13. Visual Language

Use visual concepts based on:

- lines
- stages
- progression
- hierarchy
- connected nodes
- numbered steps
- whitespace
- typography
- subtle borders

A recurring visual metaphor should be:

> uncertainty → structure → clarity → MVP

The framework should feel like a system rather than a decorative infographic.

---

# 14. Typography

Start with a modern, highly legible sans-serif.

Preferred options:

- Geist
- Inter

Do not introduce multiple typefaces unless there is a clear design reason.

Typography should carry much of the visual identity.

Large headlines should have generous whitespace.

Body text should remain highly readable.

---

# 15. Color Direction

Start with a restrained palette.

Suggested initial values:

Background:
#FAFAF8

Primary text:
#111111

Secondary text:
#666666

Borders:
#DDDDDD

Do not introduce a large color system at the beginning.

A distinctive MVPCompanion accent color can be introduced later once the visual direction has been tested.

---

# 16. Layout

Use a centered content system.

Initial maximum content width:

approximately 1200–1280px.

Use generous vertical spacing.

The website should feel spacious rather than dense.

Avoid filling every available area.

---

# 17. Motion

Motion should be subtle.

Potential future interactions:

- stage progression
- hover states
- scroll-based framework reveal
- stage highlighting
- subtle line animations
- progressive clarification visualizations

Do not introduce motion simply for decoration.

Animation should communicate structure or progression.

- understandable

- unsupported statistics
- empty superlatives

> Does this make MVPCompanion clearer?

If not, remove it.

The site should demonstrate the same principle as the method:
